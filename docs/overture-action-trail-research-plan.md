### Astra's workflow review (2026-10-09)

Astra recommends reading an Assembly's action reports and floor proceedings once, extracting the decisions report-first, then mapping them to the submitted proposals. That avoids repeating a whole-volume search for every overture. Apply this sequence:

1. Reconcile the page-qualified originating roster: source body, title/subject, page, and proposal wording. Preserve distinct same-number submissions; exclude only verified reprints or locator-only mentions.
2. Read the Overtures Committee report and floor proceedings in sequence, then relevant committee reports and CCB advice. Capture each recommendation and actual Assembly disposition once, including amendments/substitutes, defeated motions, recommittals, and exceptions to adoption in gross. Use Markdown routinely; inspect the official PDF only for missing, damaged, ambiguous, or conflicting passages.
3. Join each extracted action to the exact source-page record using sponsor, subject, wording/version, originating Assembly, and referral context. Number is a retrieval hint, never sufficient join evidence. Keep answers by reference on the referring record and link the target's independent trail.
4. Add earlier advice and later actions from the candidate index. Follow constitutional amendments through the exact sent-down wording, presbytery tallies, and later Assembly action. Keep unresolved cross-Assembly follow-up in a separate queue.
5. Close the full originating Assembly roster and action matrix. Every record needs a supported terminal action or a specific sourced gap. Then run one full validating site build for the completed Assembly; rebuild only to resolve a failed build or substantive correction.

### Operating workflow (use this instead of restarting the planning discussion)

The existing categorized candidate index is the shared search surface. Do not build another corpus-wide extract before using it. For each Assembly, the `overture_action_candidates` rows are the evidence packet; `overture_action_candidate_reviews` is its disposition matrix; the source-linked events and research ledger are the deliverable. Keep report reading Assembly-wide and record research overture-specific only when joining verified actions.

1. **Open the batch.** Freeze the Assembly's page-qualified roster from `OVERTURES.md` and its research ledger. Identify carryovers and linked overtures by source page, proposal wording, sponsor, and referral history. Keep same-number submissions distinct.
2. **Read the action sequence once.** Use the candidate index to locate the Overtures Committee and floor-action pages, then read those Markdown sections in proceedings order. Capture recommendations and actual floor outcomes as separate decisions, including substitutes, amendments, recommittals, defeats, exceptions to adoption in gross, and answers by reference. Consult CCB/permanent-committee advice and the Presbytery-vote/final-approval candidate categories in the same batch pass.
3. **Disposition every candidate.** For each candidate passage, record one explicit review result: linked to one or more page-qualified record IDs; rejected as an index, reprint, passing mention, or unrelated action; or unresolved with the reason. A matching number alone is never a join. Preserve continuation pages and contextual passages when an action crosses a page break.
4. **Build each trail from the matrix.** Add only material actions to the distinct record they actually concern. Retain exact contiguous source text and source page anchors. Use Markdown as routine evidence; check a PDF only to settle missing, corrupted, ambiguous, or conflicting text. Follow constitutional amendments into later Presbytery tallies and Assembly confirmation, using the exact approved wording as well as BCO section to establish continuity.
5. **Close the Assembly packet.** Reconcile every roster record and candidate disposition; check event identity, chronology, joins, source locators, excerpt labels, final disposition, and explicit gaps. Records can be complete with a supported terminal action or an explicit, sourced finding that a stage is not applicable. Keep unresolved future action in a separate follow-up queue without reopening a closed candidate packet.
6. **Build once.** After the whole Assembly packet closes, run the required full validating build and inspect generated diffs and representative pages. Do not build after each overture. If a substantive correction is needed, rebuild after applying it.
