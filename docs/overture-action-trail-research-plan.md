### Astra's workflow review (2026-10-09)

Astra recommends reading an Assembly's action reports and floor proceedings once, extracting the decisions report-first, then mapping them to the submitted proposals. That avoids repeating a whole-volume search for every overture. Apply this sequence:

1. Reconcile the page-qualified originating roster: source body, title/subject, page, and proposal wording. Preserve distinct same-number submissions; exclude only verified reprints or locator-only mentions.
2. Read the Overtures Committee report and floor proceedings in sequence, then relevant committee reports and CCB advice. Capture each recommendation and actual Assembly disposition once, including amendments/substitutes, defeated motions, recommittals, and exceptions to adoption in gross. Use Markdown routinely; inspect the official PDF only for missing, damaged, ambiguous, or conflicting passages.
3. Join each extracted action to the exact source-page record using sponsor, subject, wording/version, originating Assembly, and referral context. Number is a retrieval hint, never sufficient join evidence. Keep answers by reference on the referring record and link the target's independent trail.
4. Add earlier advice and later actions from the candidate index. Follow constitutional amendments through the exact sent-down wording, presbytery tallies, and later Assembly action. Keep unresolved cross-Assembly follow-up in a separate queue.
5. Close the full originating Assembly roster and action matrix. Every record needs a supported terminal action or a specific sourced gap. Then run one full validating site build for the completed Assembly; rebuild only to resolve a failed build or substantive correction.

## Decisions

1. Resolve each record from the reconciled catalogue first, using Assembly, number, source page, title, and sponsor. Never join by Assembly and number alone.
2. Read the repository Markdown minutes as the routine source. Use PDFs only for missing, corrupted, ambiguous, or conflicting passages.
3. Research one Assembly at a time. Read each relevant action report and its floor disposition once, then map the documented decisions to distinct submitted overtures.
4. Keep committee recommendations, floor motions, Assembly decisions, presbytery votes, and later Assembly confirmation as separate events. By-reference answers stay on their own records and link to the target record.
5. Build a site preview only after the full Assembly batch is researched and reviewed.

## Phases

### 1. Stabilize record identity and catalogue scope

- Reconcile the 1,537 target against the reader-facing catalogue by source-page identity; document every addition, removal, merged reprint, or locator-only occurrence.
- Repair the GA46 inventory anomalies already found: Overture 27's source heading is missing from the parsed catalogue, and Overture 13's title in the derived title row was inherited from the adjacent proposal.
- Make the same page-qualified record identity available to the page renderer, action ledger, search index, authority index, and provision-evidence projection. Join body evidence only to the exact record/page. Add an explicit migration path where a corrected locator changes an existing ID.
- Separate excerpt status from text kind so an editorial source note cannot render as a quotation.

**Exit condition:** the reconciled list, source records, research ledger, events, page map, search rows, and provision/authority projections identify the same distinct overtures; all reused-number cases remain distinct; catalogue count differences are accounted for.

### 2. Prepare one Assembly evidence packet

Use the existing candidate index to filter passages for that Assembly and produce a compact queue containing:

- the distinct-record roster, sponsor, subject, originating pages, and proposal text;
- CCB advice, committee recommendations, amendments/substitutions, floor disposition, and grouped adoption statements;
- presbytery vote summaries and later Assembly votes for constitutional proposals;
- source page anchors and neighboring Markdown context; and
- a decision field per candidate: linked to record ID, rejected as unrelated/index/reprint, or unresolved.

Candidate mentions and automated pattern matches are retrieval hints only. They must never create a record link without source, subject, text-version, and action-context review.
The current literal mention parser misses forms such as `O-2021-41`, year-number forms such as `Overture 2021-41`, and comma/range lists. Extend candidate extraction to capture these without treating the captured number as a verified join. Preserve the source passage and surrounding report context.

**Exit condition:** every candidate passage in the Assembly packet has a recorded disposition, including candidates that were considered and rejected.

### 3. Extract actions report-first

Read the Assembly's CCB, Overtures Committee, relevant permanent-committee reports, and floor minutes in proceedings order. Capture each material recommendation/action once with its exact excerpt, actor, result, minutes locator, and anchor. Map it to an originating overture by source, proposal text, and referral context. For adoption in gross, verify whether the item was included, excluded, amended, or handled separately.

For each overture, add the applicable events and describe terminal results or unresolved gaps. Follow constitutional amendments through the presbytery process and second Assembly vote. Stop searching for unrelated future action after the proposal has a supported terminal result. Record by-reference answers on the referring record and preserve the target's independent trail.

**Exit condition:** every catalogue record is either complete or has a specific gap note and an explicit list of sources/Assemblies searched. No event is based solely on an index, number match, digest, or BCO section match.

### 4. Close and build the Assembly batch

Before building, check record/event joins, duplicate IDs, related-record links, exact cited page excerpts, disposition alignment, and event order. Then run the repository's full validating `siteBuild` via `pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/build-local.ps1 -RegenerateOvertures` because curated overture-source artifacts changed. Inspect all generated diffs and affected local-preview pages. Fix discrepancies before beginning the next Assembly.
